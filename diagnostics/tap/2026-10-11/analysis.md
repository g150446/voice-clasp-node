# ソフトウェアタップ判定の精度改善（2026-10-11）

## 問題

`592b0f8` で導入したソフトウェア分類器（`nordic-main/src/tap_detector.c`）は、
斜め45度姿勢でダブルタップをシングルに誤分類した。2026-10-05 の実機記録では、
`max_pulse_ms` を 40→100 ms に広げる一時回避で 1 試行だけ成功し、既定の 40 ms には
反映されないまま残っていた（`diagnostics/tap/2026-10-05/analysis.md`）。

## 真因

判定器は **ボード座標系** で衝撃を測っていた:

- `az = |linear[2]|`（ピーク・エッジ）、`lateral = max(|linear[0]|,|linear[1]|)`
- 衝撃幅の quiet タイマーは `amplitude = max(az, lateral)`
- 候補ゲートに `az >= dominance * lateral`（Z 軸支配）を要求

タップ方向は重力でもボード Z でもなく、**打った面と手首向きで任意軸**に出る。
保存波形を本番 C と同じ射影で解析した結果:

| トレース | 衝撃の分布 | 旧 Z 支配ゲート |
|---|---|---|
| `45deg_double_1` | 重力法線に寄る | 通る（が ring で幅超過） |
| `45deg_double_60ms` | ほぼ横軸（proj an=0.31 / lat=5.56） | 棄却 |
| `45deg_double_100ms` | ほぼ横軸 | 棄却 |

ボード Z に直交する衝撃では `az` が立たず dominance で棄却、加えて横方向 ring で
`amplitude` が quiet を下回らず幅 40 ms を超過 → **1 打目が broad 棄却** →
`pending` が立たず 2 打目のみ有効 → double が single 化。幅を 100 ms にするのは
この ring を丸ごと許す対症療法で、振動耐性を落とす。

## 修正

座標軸の支配を捨て、**加速度ベクトルの大きさ**で判定する
（姿勢・方向ともに不変）。`linear = accel - gravity`（重力ローパスは従来どおり）とし、

- `magnitude = |linear|` をピーク・エッジ・quiet・衝撃幅のすべてに使用
- 軸支配ゲート（`dominance`）を**廃止**（フィールドは BLE ワイヤ互換のため予約、未使用）
- タップと腕の動きの分離は、**立ち上がり(max_rise)＋エッジ＋ピーク＋幅上限**に一本化

既定値（`tap_detector.h` の `TAP_CONFIG_DEFAULT`、ビルドへ反映）:

```
quiet_g 0.50  peak_g 1.0  edge_g 0.30  dominance 0.0(予約)  gravity_alpha 0.015  noise x4.0
pre_quiet 15  max_rise 15  post_quiet 20  max_pulse 40  min_gap 80  max_gap 350  cooldown 700  suppress 1500
```

## 未検証（実機必須）→ 2026-10-11 実機 held-out を実施

OTA 0.0.113（板Z支配ゲート廃止・大きさ判定）を実機へ適用後、`tap_lab.py capture`
で **45度姿勢 held-out 5試行**を実施。波形・姿勢・config・判定flag・通知を保存。

| # | 操作 | 通知 | 波形整合 | gaps | 飽和 | 判定 |
|---|---|---|---|---|---|---|
| 1 | 45度 double | double | PASS(2496/2496一致) | 0 | 0 | OK |
| 2 | 45度 double | double | PASS | 0 | 0 | OK |
| 3 | 45度 double | double | — | **1** | 0 | 検知OK・FIFO欠落でtuning不採用 |
| 4 | 45度 激しい動き | **double** | PASS | 0 | **2** | **誤検知** |
| 5 | 45度 通常の動き | なし | PASS | 0 | 0 | OK |

**報告した本丸（斜め姿勢で double→single）は実機で解消**（45度 double 3/3 が double）。
ただし試行4で **激しい手首の動きが誤って double** 化した。原因は**±4 g の動的範囲不足**:

| 波形 | 最大 |g|（=max raw×gto） | raw≥32760(clip)サンプル |
|---|---|---|
| 45度 double（本物のタップ） | 3.996 / 3.994 | 0 |
| 45度 激しい動き（誤検知） | 3.997 | 2 |

本物のタップも誤検知の jerk も **±4 g の天井（≈3.997 g）に張り付く**ため、
大きさ・幅・立ち上がり・極性・飽和フラグのいずれでも分離不能（極性は両者とも同方向、
duration/rise/peak も重複）。**飽和をタップ棄却に使うと本物のタップも棄却**し退行した
（実装して保存8波形＋新45度doubleで regress を確認し撤回）。

### 次の打ち手（±8 g を実施→却下）

フルスケールを ±8 g へ拡大（0.0.114）して実機held-outを再採取した結果:

| 項目 | ±8 g 実測 |
|---|---|
| 本物の45度 double（tuning可の2本） | **5.61 / 7.57 g（非クリップ）** → 範囲不足がタップのクリップ原因と確定 |
| 通常の腕の動き（3試行） | 最大 0.61–0.91 g、誤検知なし |
| 激しい jerk の再再現 | このsessionでは3試行とも ≤0.9 g（暴力的な再現に失敗）→ 極端ケースは未再測定 |

**±8 g は却下**。理由は**同じ加速度センサがジェスチャ経路を駆動**しているため:
`GESTURE_LIFT_ACCEL_MIN_MS2 = 0.40` m/s²（≈0.041 g）や `GESTURE_STOP_OPP_*`（0.15–0.25 m/s²）は
±8 g の LSB 0.244 g（≈2.39 m/s²）より小さく**1LSB未満＝分解能不能**で、手のひら起こし・静止判定が壊れる。
`peak_g` を上げても、暴力的 jerk は ≥4 g（タップ 4.97–7.6 g と同値域）で分離不能。**範囲でも閾値でも
極端jerkの誤検知は取れない**（単一IMUの物理限界）。0.0.115で ±4 g へ巻き戻し、ジェスチャ分解能を回復。

保存タップ全件の最小ピーク 4.97 g・動きの最大 0.73 g の間隔は大きく、
**通常の反復では大きさ判定＋peak_g 1.0 g で誤検知なし・斜めdoubleも解消**。残るは
限界まで振り抜いた jerk のみ。

通常の反復（検知率・誤検知率の統計的保証）には不足。運転振動の代用データも未取得。
