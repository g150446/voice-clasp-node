# シングルタップ（`0x14`）イベント対応

> ファームウェア **0.0.94+**: single (`0x14`) / double (`0x12`) は **notify-only**。
> 録音 start/stop はホストが RX `0x01` / `0x00` で指示する（パススルー中の single はページ送り専用）。
> **0.0.95+**: 手首ジェスチャーは検出スイッチ（RX `0x07`）既定 OFF。ON 時のみ Node 自律
> （TX `0x01`/`0x02`）。日常の既定操作はシングルタップ。

関連:

- ファーム仕様: [`nordic_main_guide.md`](nordic_main_guide.md) の「シングル／ダブルタップ」
- 実装: `nordic-main/src/main.c`（`EVT_SINGLE_TAP` / `process_tap_event`）

## 現状

| 層 | 状態 |
|----|------|
| ファーム `0.0.95+` | single/double は notify-only。録音は RX（既定）またはジェスチャー（opt-in） |
| Mac クライアント | `0x14` 任意デバッグ表示 |
| **Android アプリ** | `0x14` でホスト承認録音、またはパススルー時はページ送り |

## プロトコル（Android が受けるもの）

### BLE 基本

| 項目 | 値 |
|------|-----|
| デバイス名 | `HarnessNode` / `HarnessNode-Echo` |
| Service | `00000001-0000-1000-8000-00805f9b34fb` |
| TX（Notify） | `00000002-0000-1000-8000-00805f9b34fb` |
| RX（Write） | `00000003-0000-1000-8000-00805f9b34fb` |

イベントパケット（TX notify）:

```
[0x00][0x55][code][+ optional payload]
```

### タップ関連コード

| code | 名前 | payload | 意味 |
|------|------|---------|------|
| `0x12` | `double_tap` | なし | ダブルタップ / Echo double click |
| **`0x14`** | **`single_tap`** | **なし** | シングルタップ / Echo single click |
| `0x21` | `sleep_wake` | なし | ライトスリープ復帰（タップでも発生し得る） |
| `0x01` / `0x02` | recording start/stop | なし | 録音開始／停止（ジェスチャー **または** ホスト RX 後） |

**注意:** `0x13` は別用途（IMU sample デバッグ）。`single_tap` は **`0x14` 固定**。

### ファーム側セマンティクス（0.0.94+）

| 入力 | Node の動作 |
|------|-------------|
| single (`0x14`) | **notify のみ**。録音はトグルしない |
| double (`0x12`) | **notify のみ**。録音は変えない。開始ジェスチャー候補を破棄 |
| 手首ジェスチャー | 従来どおり自律で `0x01`/`0x02` |
| RX `0x01` / `0x00` | ホスト指示の録音 start / stop |

ホスト側の典型 UX（Android）:

| 状態 | single | double |
|------|--------|--------|
| 通常 | RX で録音 start/stop | パイプライン割り込み |
| パススルー ON | 録音せず G2 ページ送り | パススルー終了 |
| パススルー OFF | （上の通常） | パススルー開始 + 画面抽出 |

タイミング（タップ分類）:

- 物理 1 打目の時点で HW が INT1 を assert する
- ファームは **`TAP_SRC` に触れずに 350 ms 待つ**
- 待機後に `TAP_SRC` を1回だけ読む。`TAP_IA|DOUBLE|Z` なら double、それ以外なら single
- **タップ1回につきイベントは必ず1つ**。double の直前に single は来ない
- 物理タップから BLE 通知まで約 **350〜400 ms**
- クールダウン **700 ms**（single / double 別）

認識強度（FW `0.0.97+`）:

- レジスタ `TAP_THS_6D`（`0x59`）既定 **`0x11` ≈ 1.0625 g**（FS=±2 g、0–31 の 32 段階）
- 大きいほど反応しにくい。実行時は RX `0x50` / `tap_monitor.py --write` で変更可

ホスト承認の追加レイテンシ（録音開始）: primary 接続で典型 **+50–150 ms**（BLE 往復）。
FW `0.0.100+` では接続アイドル時の primary 間隔は 30–50 ms（タップ通知の追加遅れは最大約 50 ms）。supervision timeout / GAP PPCP は 8 s。

`0.0.102+` では、相手が ACK を返さなくなったときに制御系の通知を最大 20 ms 待って破棄する（`notify_one()`）。タップ通知が落ちた回数はシリアルの `>>> HB ... ndrop=` と `>>> DISCONN ... ndrop=` で数えられる。以前はここで無期限にブロックし、ウォッチドッグがデバイスをリセットしていた。

ライトスリープ中のタップ: 先に `0x21`、続けて `0x12` または `0x14` が来ることがある。

未接続 3 分後の SYSTEMOFF 中は **ダブルタップだけ** が起床する（リセットしてアドバタイズ再開）。単タップでは起きない。

## Android実装

1. **イベントパーサ** — `0x14` を `single_tap` として分岐（実装済み）

2. **ログ／デバッグ UI** — single / double カウンタ表示（実装済み）

3. **UX（0.0.94+）**
   - single: パススルー中は RX なし（G2 ページ）。それ以外は RX `0x01`/`0x00` で録音。
   - ローカルで RECORDING を立てず、必ず TX `0x01`/`0x02` に追従。
   - double: パススルー ON/OFF トグル（OFF 時は抽出開始）。処理中は割り込み優先。
   - ジェスチャー録音は Node 自律のまま。

4. **互換**
   - **FW 0.0.94 とアプリをセットで更新**すること。
   - 旧 FW (≤0.0.93) は single で自律録音するため、新アプリと組み合わせると挙動がずれる。

5. **回帰**
   - single → `0x14` のみ（直後の自律 `0x01` なし）
   - ホスト RX `0x01` → `0x01` + PCM
   - ホスト RX `0x00` → `0x02`
   - double → `0x12` のみ
   - ジェスチャー開始（通常）は従来どおり `0x01`/`0x02`
