# シングルタップ（`0x14`）イベント対応

> Androidアプリとファームウェアの対応済み仕様。singleは診断ログのみで、Kindle/G2操作はdouble専用。
> ファームウェア **0.0.87** で single / double 同時運用を実機確認済み（2026-08-31、10/10 PASS）。

関連（実装済み）:

- ファーム仕様: [`nordic_main_guide.md`](nordic_main_guide.md) の「シングル／ダブルタップ」
- 実装: `nordic-main/src/main.c`（`EVT_SINGLE_TAP` / `process_tap_event`）

## プロトコル（Android が受けるもの）

### BLE 基本

| 項目 | 値 |
|------|-----|
| デバイス名 | `HarnessNode` |
| Service | `00000001-0000-1000-8000-00805f9b34fb` |
| TX（Notify） | `00000002-0000-1000-8000-00805f9b34fb` |
| RX（Write） | `00000003-0000-1000-8000-00805f9b34fb` |

イベントパケット（TX notify）:

```
[0x00][0x55][code][+ optional payload]
```

### タップ関連コード

| code | 名前 | payload | 意味 |
|------|------|---------|------|
| `0x12` | `double_tap` | なし | リストバンド表側→基板面の垂直ダブルタップ |
| **`0x14`** | **`single_tap`** | **なし** | 同上のシングルタップ（間隔窓を超えた単独衝撃） |
| `0x21` | `sleep_wake` | なし | ライトスリープ復帰（タップでも発生し得る） |
| `0x01` / `0x02` | recording start/stop | なし | 録音開始／停止（ジェスチャー or 運転モード double） |

**注意:** `0x13` は別用途（IMU sample デバッグ）で使われている。`single_tap` は **`0x14` 固定**。

### ファーム側セマンティクス（Android 設計の前提）

| モード | `0x14` single | `0x12` double |
|--------|---------------|---------------|
| 通常 | BLE 通知のみ。録音は変えない。ジェスチャー開始候補を破棄 | 同左 |
| 運転 | **BLE 通知のみ**（録音トグルなし） | primary 接続中に録音開始／停止トグル。併せて `0x01`/`0x02` が出ることがある |

タイミング:

- 物理 1 打目の時点で HW が INT1 をassertする（`MD1_CFG` に single も割り当てているため）
- ファームは **`TAP_SRC` に触れずに 350 ms 待つ**。ここで読むとラッチが解除され、
  進行中のダブルタップ判定が壊れる（0.0.76〜0.0.86 の `0x12` 消失の真因）
- 待機後に `TAP_SRC` を1回だけ読む。`TAP_IA|DOUBLE|Z`（`0x51`/`0x59`）なら double、
  それ以外（実測 `0x00`）なら single
- したがって Android から見ると、**タップ1回につきイベントは必ず1つだけ**。
  double の直前に single が来ることはない
- 物理タップから BLE 通知までの遅延は約 **350〜400 ms**（single / double とも同じ）
- クールダウンは **700 ms**、single と double で別々（0.0.81〜）

ライトスリープ中のタップ: 先に `0x21`、続けて `0x12` または `0x14` が来ることがある。

## Android実装

1. **イベントパーサ**（実装済み）
   TX notify の `[0x00, 0x55, code]` で `code == 0x14` を `single_tap` として分岐する。  
   未知コードとして捨てない。

2. **ログ／デバッグ UI**（実装済み）
   少なくとも double と同様に画面または logcat に `single_tap` を出す（動作確認用）。

3. **UX**
   singleは診断ログのみ。録音、Kindle操作、グラス表示には使用しない。

4. **既存 double 処理との共存**  
   - double 専用ロジックを single に流用しない  
   - 運転モードで `0x12` のあとに `0x01`/`0x02` が続く既存パスを壊さない

5. **回帰**  
   - 通常: 1 タップ → `0x14` のみ（録音開始しない）  
   - 通常: ダブル → `0x12` のみ  
   - 運転: ダブル → 録音トグル + `0x12`  
   - 運転: シングル → `0x14` のみ（録音不変）

## 参照実装・実機検証（Mac）

- `mac_client/tap_monitor.py` — TX通知を全件ダンプする。`0x12` / `0x14` に加えて
  診断イベント `0xD0`（レジスタスナップショット）/ `0xD1`（生 `TAP_SRC`）/ `0xD2` を
  デコードし、`--write REG:VAL` でOTAなしにIMUレジスタを振れる。
  開始・終了時に音を鳴らすので、1人で叩きながら計測できる。
- `mac_client/image_state.py` — 稼働中のスロット構成を読むだけの確認用。
- `mac_client/xiao_voice_client.py`、`mac_client/gesture_monitor.py` — 既存クライアント。

Androidが受け取れない場合は、まず `tap_monitor.py` でMac直結で受かるかを見る。
Macで受かるならAndroid側、Macでも受からないならファーム側と切り分けられる。
